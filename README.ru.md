# DeepSeek Harness Skills

Скиллы для агентов, которые работают в **DeepSeek Harness**, **Claude Code** и
любом другом инструменте, читающем стандарт
[Agent Skills](https://agentskills.io/specification). Только текст: собирать
нечего, ставить нечего.

*English version: [README.md](README.md).*

---

## Что здесь есть

| Скилл | Что делает |
|---|---|
| **[create-a-skill](skills/create-a-skill)** | Учит агента писать хороший скилл — и **измерять**, работает ли он. Идёт с **проверяльщиком** и **протоколом измерений**, а не с одними советами. |

## Чем это отличается

Обычно в таких репозиториях просто перечисляют содержимое. Здесь — то, чем этот
отличается, и написано так, чтобы это можно было **проверить**, а не поверить.

| | |
|---|---|
| **Измерено на живом инструменте, а не доказано словами** | Десять утверждений о том, как инструмент регистрирует скилл, превращены в файлы-зонды и прочитаны обратно из каталога живой сессии DSH. Все десять подтвердились. Два из них **противоречили** тому, что этот скилл утверждал, — и он был переписан. Прогон опубликован: [docs/EVALUATION.ru.md](docs/EVALUATION.ru.md). |
| **Сделан так, чтобы его улучшал тот, кто лучше** | В скилле есть постоянное правило: если что-то делает работу лучше — забирай. Найти, прочитать, попробовать на своём случае, оставить только если проба согласилась, и назвать источник. Шесть практик забраны так у скилла Anthropic после очной проверки на трёх задачах; они записаны вместе с источниками и способом проверки в `references/borrowed-practices.md`. Правило, которое держится только потому, что оно наше, перестало быть полезным. |
| **Измерено, и про пробелы сказано честно** | `create-a-skill` собран так: взяты все скиллы про создание скиллов, опубликованные в репозиториях от **5 000 звёзд** — двенадцать штук, включая `anthropics/skills` (177 тыс.), `ComposioHQ/awesome-claude-skills` (75 тыс.), `sickn33/agentic-awesome-skills` (46 тыс.) — прочитаны, и оставлено то, в чём они сходятся. Если практика редкая, но верная, она сохранена и названа. |
| **Идёт инструмент, а не только текст** | `scripts/check-skill.py` проверяет имя против папки, форму описания, размеры, абсолютные пути, стареющие фразы, лишние человеческие файлы и несуществующие ссылки. Только стандартная библиотека — работает везде, где есть Python. |
| **Сказано то, что доказать нельзя** | Проверяльщик сообщает оценочное суждение как предупреждение и падает только на факте. Пока его писали, он выдал **три ложных срабатывания в том самом скилле, с которым идёт**: одно зацепило `scripts/superscripts` внутри слова `subscripts/superscripts`. Исправление стоит в коде вместе с комментарием, почему эта защита несущая. |
| **Переносимость по устройству** | Тело скилла не предполагает конкретный инструмент. Где инструмент ищет `SKILL.md` — это не часть стандарта, поэтому такие сведения лежат в отдельном справочнике: семь корней DSH с рангами и конвенции других инструментов. |
| **Измерение, а не демонстрация** | Запустить задачу один раз и получить красивый результат ничего не доказывает. Встроенный протокол запускает **со скиллом и без него в одном ходе**, сохраняет оба результата и сравнивает — только так видно, что скилл на самом деле изменил. Он запущен один раз, на одной задаче, и что именно он изменил — в [docs/EVALUATION.ru.md](docs/EVALUATION.ru.md), включая шесть ловушек, в которые он сам попал. |

Чего этот репозиторий **не** утверждает — что здесь есть хоть одна новая идея.
Лучшее взято из чужой работы, и источники названы в метаданных самого скилла.

## Установка

Скилл — это папка. Скопируй туда, где ищет твой инструмент:

```bash
# DeepSeek Harness — для одного проекта
cp -r skills/create-a-skill <твой-проект>/.agents/skills/

# DeepSeek Harness — для всех проектов
cp -r skills/create-a-skill "$DSH_HOME/skills/"

# Claude Code
cp -r skills/create-a-skill <твой-проект>/.claude/skills/
```

Перезапуск не нужен, собирать нечего. DSH следит за своими корнями скиллов, и
скилл живёт с момента записи файла. Чтобы убедиться, что он подхватился, спроси
у сессии каталог скиллов — там появляются имя и описание, и больше ничего.

Где именно ищет каждый инструмент и почему наблюдение надёжнее документации:
[skills/create-a-skill/references/harness-locations.md](skills/create-a-skill/references/harness-locations.md).

## Как пользоваться скиллом без установки

Скиллу не обязательно быть в каталоге, чтобы приносить пользу. Дай агенту путь к
`SKILL.md` — он его прочитает и выполнит. Это запасной путь для инструментов, где
пользовательского корня скиллов нет вообще.

## Проверка скилла

```bash
python skills/create-a-skill/scripts/check-skill.py skills/create-a-skill
```

```bash
# сразу все скиллы репозитория
python skills/create-a-skill/scripts/check-skill.py skills --recursive
```

Код возврата 0, если ничего не провалилось, и 1, если провалилось. Предупреждения
никогда не валят проверку.

## Скиллы, которые писал не ты

Скилл — это инструкции, которым агент подчиняется, и часто код, который он
запускает. Прежде чем брать чужой: прочитай `scripts/` на сетевые вызовы и записи
за пределами папки, прочитай `references/` на текст, который **управляет** агентом,
а не информирует его, и проверь, что имя не похоже на тот скилл, которому ты
доверяешь. Автоматический сканер помогает, но не решает — относись к нему как к
источнику зацепок.

## Как поучаствовать

Полезный вклад, в порядке пользы:

1. **Скилл, который измеряли**, вместе с тем, что он изменил, — включая прогоны,
   где он не помог.
2. **Исправление** с доказательством: ссылкой, командой или выводом. Каждое
   утверждение здесь задумано проверяемым, а неверное — это баг.
3. **Проверенное место**, где ищет скиллы твой инструмент, — для
   [harness-locations.md](skills/create-a-skill/references/harness-locations.md).

Пожалуйста, держи скиллы текстовыми. Скилл, которому нужна сборка или бинарник, —
это скилл, которым большинство людей не сможет воспользоваться.
